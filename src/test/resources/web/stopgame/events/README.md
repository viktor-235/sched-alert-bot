# Naming convention for HTML test files

HTML-файлы в этой директории используются для unit и интеграционных тестов процессора StopGame.

## Принципы нейминга

- Имя файла отражает состав и статусы событий на странице.
- Каждое событие обозначается буквой (a, b, c, ...), которая уникальна в рамках тестов.
- Каждая буква соответствует конкретному id события независимо от файлов.
- Если у события есть особый статус, он указывается через дефис после буквы:
    - `_live` — событие в прямом эфире
    - `_new_desc` — обновлено описание события
    - `_new_date` — обновлена дата события
    - `_old_desc` / `_old_date` / `_past_date` — в seed у события старое описание / старая дата / дата в прошлом
    - `_old_participants` — в seed у события старый список участников
    - `_canceled` / `_finished` — событие в статусе CANCELED / FINISHED (в seed или в ожидаемой базе)
    - `_returned` — событие вернулось на сайт после CANCELED / FINISHED
- События перечисляются в том же порядке, что и на странице.
- Если файл содержит некорректный HTML, добавляется суффикс `_broken`.
- Если на странице нет событий, используйте имя `empty.html`.

## Примеры

- `a-b-c.html` — три обычных события (a, b, c)
- `a_live-b-c.html` — событие a в статусе LIVE, b и c — обычные
- `b-с_add_desc.html` — в событии c обновлено описание, b — обычное
- `a.html` — одно обычное событие
- `empty.html` — событий нет
- `broken.html` — некорректный HTML

## JSON-файлы

- `*-parsed.json` — ожидаемый результат парсинга html-файла
- `*-seed.json` — начальное состояние базы
- `*-db-expected.json` — ожидаемое состояние базы после обработки
- `*-msg.json` — ожидаемые сообщения в Telegram

Буква `d` — событие, которого нет ни в одном html-файле (только в seed).

## Переиспользование

Один html-файл может использоваться для разных тестов с разными начальными и ожидаемыми состояниями базы (json-файлы).
Это позволяет минимизировать количество html-файлов и упростить поддержку тестов.
